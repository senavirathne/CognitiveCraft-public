All names in this file are **new proposals**, except the explicitly cited existing SPI. Java implementations use records/sealed results in separately owned namespaces; these are semantic signatures, not new existing repository symbols. Every wire DTO uses contract.schema.json. ## Exact identity, digest and metadata semantics

Storage identity is (world UUID, storage UUID). Native incarnation is (world UUID, dimension, block coordinates, server-created incarnation UUID, marker generation). These are distinct: a rename preserves the first; replacement invalidates the second. Coordinate equality does not establish continuity.

Selection before registration must not create a persistent native marker. SelectionWitness therefore uses SelectionMember with a server-local live_instance_token, actual block registry ID and observed coordinates, plus server lifecycle_epoch/selection_revision. The server keeps the exact block-entity instance, topology and displayed confirmation summary behind that token. It is short-lived memory, not a grant or persistent binding. On confirmation recheck the same instance, topology, current reach/protection and caller. Any changed summary requires a fresh confirmation; restart invalidates the witness. Only after explicit authorization does registration create/persist a marker. Existing registered endpoints additionally revalidate their PhysicalStorageBinding. Clients/models cannot mint or supply these trusted tokens by claiming a UUID.

`topology_sha256 = SHA256(canonicalJSON({adapter_id, world_id, dimension, members, facing}))`. Canonical JSON includes its final LF. Members are ordered by (x,y,z,incarnation_id), and each member includes coordinates, incarnation ID and marker generation. Chests face NORTH/SOUTH/EAST/WEST. Double members are horizontal neighbors perpendicular to facing; the native adapter additionally verifies the actual complementary LEFT/RIGHT block states. Barrels may face UP/DOWN. Opening a lid is not a topology change. A normal chest becoming a double chest or splitting changes the binding generation and requires authorized rebind. Each synthetic positive binding has its digest actually calculated from these bytes.

Revisions are monotonic within one live metadata history. Generation changes when identity authority is invalidated/rebound, not on every observation. Lifecycle epoch is a server-lifetime fence, freshly minted after restart. Metadata rollback plus a newer native world is ambiguous and remains UNVERIFIED; no UUID counter is a defense against restoring both histories. A owns coordinated world/save recovery. Metadata snapshots never make promises about cross-participant atomic durability.

StorageRoleAssignment keys (world, beneficiary, role) point to one storage UUID and generation. PUBLIC is not a beneficiary. A public or organization-owned chest can be Ada's default if Ada is authorized; assignment does not change owner or grant access. Role assignment lookup checks both current beneficiary control and storage permission. Record roles describe purpose only. Owner/ACL/role edits increment their appropriate revisions and invalidate decision caches. Ownership transfer clears inherited grants by default and requires an explicit new policy; do not accidentally preserve former-owner control.

ItemKey's component fingerprint is computed by the native item adapter from the installed registry's canonical default component representation using the game's verified codec, with algorithm/model/game version in evidence. Non-default components, container-bearing stacks and unsupported codec values are refused. The fingerprint in synthetic fixtures is an opaque test value, not a claim about the 26.3 item codec. D05 must document the exact codec it verifies. Item display names alone never select slots or prove equality.

## Authority and concurrency

Authenticated caller/world/domain comes from server ingress. The opaque in-process world authority capability is constructed only by the dedicated test fixture mod in a tagged test world, or by A after J02. It is never serialized, accepted from chat or produced by decoding this JSON. No public convenience constructor supplies production authority. New production adapters have no self-registering initializer; C/D fixture entrypoints, mixes and authority factories stay outside the release JAR.

A locks original actor and relevant storage/recipient resources in a consistent stable-identity order and rechecks all preconditions in the server tick performing an effect. D's independent test driver can exercise the same guarded component operation but cannot impersonate A's leases. An ACL decision valid for at most two ticks still requires effect-time recheck; an interleaved revision invalidates it immediately. Native protection may veto a mod ACL allow. Deposit-only output may confirm capacity/acceptance to the actor without disclosing existing stock to the player.

Participant-save confirmation requires authentic A evidence for every mutated participant with native save lineage and original effect/owner. Higher-tier JSON fixtures exercise codec expectations only. D may emit LIVE_OBSERVED; only A can issue JOURNAL_ACKNOWLEDGED, PARTICIPANT_SAVES_CONFIRMED or ORIGINAL_OWNER_SETTLED projections after its actual protocol qualifies. Equality of live counts is insufficient, including after restart. Foreign stock cannot discharge original custody.

## Errors and migration

Every error is one of the schema BlockerEvidence codes with KNOWN/UNKNOWN and AUTHORIZED_FACTS/REDACTED provenance. Do not disclose hidden storage IDs in redacted errors. Source omissions and multiple visible matches clarify; truncated discovery is UNKNOWN. Unsupported endpoints/items refuse before any withdrawal. No implicit nearest fallback or player-inventory access.

Transport version 1.0.0 is independent of A journals, B planning formats and metadata schema_version 1. Unknown versions/fields fail closed. A future coordinated amendment must publish new canonical bytes, changelog, old/new positive and negative fixtures, migration and rollback compatibility, and an external manifest hash; both agents verify it before advancing. Existing A readers must precede J writers. An unqualified adapter blocks its J gate, not unrelated independent C/D work.
